\chapter{Prediction Model Design}
\label{ch:method}

The predictor receives the audit prefix $X_t$ and returns one
probability for each of the 18 action categories. Its two principal
inputs are the order in which records reached the collector and
the observed relationships among records. Order can locate an
event relative to preceding activity. Target membership can
distinguish which of several earlier outcomes belongs to the object
currently in view. The design retains a sequence path so the
predictor can still use received events when the available records
do not identify an eligible target.

The comparisons vary three design choices. The event-only and
flat attention models test how much a forecast can recover from
order and flexible history retrieval. THM and REL add explicit
observed target membership, while varying whether they summarize
each group before or after modeling relationships among events.
The Local and Final History variants retain a target-aware readout
and vary the recurrent state attached to each event. The sequence
and relation paths of the original residual predictors are shown
in Figure~\ref{fig:model}.

\section{Receipt-order predictor}

The event encoder maps each admitted START or END to a vector $e_i$.
A gated recurrent unit (GRU)~\cite{cho2014gru} processes the resulting
sequence in receipt order. For the event-wise checkpoints used in
the later comparisons, its state advances as
\begin{equation}
  h_i = \operatorname{GRU}(e_i,h_{i-1}),
  \qquad z_{\mathrm{event}} = f(h_T).
  \label{eq:eventgru}
\end{equation}
Here $T$ is the number of admitted events and $f$ outputs 18 action
scores. The softmax of these scores is the event-only distribution.
A zero-initialized history handles a boundary with an empty prefix.
The flat history attention comparator adds a history-conditioned
readout over the received events with a common pool.

\section{Target history and relation attention}

Let $I_g$ be the index set of received events assigned to observed
target $g$. The target history model (THM) computes a mean slot for
each nonempty target group,
\begin{equation}
  m_g = |I_g|^{-1}\!\sum_{i \in I_g} e_i .
\end{equation}
The final event-history state queries these slots and the readout
contributes a correction to the event prediction. Averaging before
the readout makes the target group the unit of retrieval in THM.
Two groups that have the same mean event representation present
the same slot to that readout. The relation
attention model (REL) first lets events associated with the same
target attend to each other. A history query then reads the
relation-enriched events. Group membership limits where the
within-target context comes from. The readout can then combine
evidence across observed groups for the same forecast. At the level
of the output head, the
original residual models can be written as
\begin{equation}
  z(X_t) = z_{\mathrm{event}}(X_t) + \Delta z(X_t,\{I_g\}),
  \qquad p(y\mid X_t) = \operatorname{softmax}(z(X_t))_y .
  \label{eq:relation}
\end{equation}
The relation path in these models uses observed membership, roles and
timing. An input without usable target evidence follows the event-only
path. Figure~\ref{fig:model} shows how identical audit evidence feeds
both the ordered history and the target readout. The equations isolate
the difference in aggregation and omit implementation-specific
projection layers.

\section{History exposure at each event}

Under interleaved benign activity, the final history vector summarizes
evidence from every admitted event. An older target-linked event can
carry a different context from the boundary's final state. The
Local History variant attaches the history state $h_i$ to the
relation-enriched representation of event $i$ before pooling. The
Final History control attaches the same final state $h_T$ to
each event. Both choices use the same input prefix and readout
structure. Replacing $h_i$ by $h_T$ changes both the states exposed to
the readout and the paths through which the recurrent encoder
receives training gradients. The comparison therefore tests these
two complete placements of history, with the same model capacity.

\section{Target-conditioned probability average}

A later comparison uses a single-history reference model $p_{\mathrm{base}}$
and a separately trained model $p_{\mathrm{dual}}$ with two independent
64-dimensional recurrent states. The two recurrent cells in the
Full Step model each receive the event history and update once
per admitted event using their standard GRU updates. The model is
trained with the action objective and the two states feed its
relation and output pathways. They do not have assigned attacker and
benign roles.

For each seed, the fixed combination averages the separately trained
probabilities on a prefix with at least one observed target.
\begin{equation}
  p_{\mathrm{mix}}(\cdot\mid X_t)=
  \begin{cases}
    \tfrac12 p_{\mathrm{base}}(\cdot\mid X_t)
      + \tfrac12 p_{\mathrm{dual}}(\cdot\mid X_t), & G(X_t)\ne\varnothing,\\
    p_{\mathrm{base}}(\cdot\mid X_t), & G(X_t)=\varnothing,
  \end{cases}
  \label{eq:mixture}
\end{equation}
where $G(X_t)$ is the set of observed target groups. The fallback copies
the full baseline distribution on a target-free prefix. The paired
controls use the same rule with a single wider recurrent model, a
BiTA-inspired aggregator, or an independently trained instance of the
baseline. The fixed average provides a test of the complete predictor.
The same-model-count controls are needed to assess the contribution
of the two-memory architecture.

\section{Observed-history frequency baseline}

For target-poor inputs, a non-neural baseline summarizes the received
START order for records with an observed action hint and indicates
whether the latest such START has a uniquely linked received END.
The key uses the hints derived from observed commands. Each training
execution contributes one vote per key, with its own labeled
occurrences averaged before voting. If $C_k$ is the resulting count
vector, $n_k$ the number of training executions supporting key $k$,
and $\pi$ the training action prior, then
\begin{equation}
  q_k = \frac{C_k+\pi}{n_k+1}.
  \label{eq:table}
\end{equation}
An unseen key returns $\pi$. In the probability-mixing comparison
on target-free inputs, the same small fixed weight is used for
either $q_k$ or $\pi$. This controls for the effect of injecting
additional probability mass independently of the key.
